# Charts and data visualisation guidelines

- Choose by question: comparison -> bars (sorted), trend -> line, composition -> stacked bar or donut (<= 5 parts), distribution -> histogram/box, relationship -> scatter, geography -> choropleth only with normalised data. Avoid 3D, dual axes, pie with many slices, truncated bar axes.
- Title states the insight ("Revenue doubled after March"), subtitle gives units and period. Label axes with units, direct-label lines/bars instead of legends, annotate the one event that matters. Source note bottom-left.
- Colour: grey for context, one accent for the story, a colour-blind-safe palette for categories (Okabe-Ito: #0072B2 #E69F00 #009E73 #D55E00 #CC79A7 #56B4E9 #F0E442 #000000). Never red/green only. Contrast against background >= 3:1.
- Clean ink: remove top/right spines, light dashed gridlines, tabular numerals, 12-14pt text on slides/PDF, consistent number formats and decimals, thousands separators.
- matplotlib: `plt.rcParams.update({"font.family":"DejaVu Sans","axes.spines.top":False,"axes.spines.right":False,"axes.grid":True,"grid.alpha":.25,"figure.dpi":110,"savefig.dpi":220})`; `fig,ax=plt.subplots(figsize=(8,4.5),constrained_layout=True)`; save PNG (and SVG for web). Check the PNG with `<view>`.
- Web charts: inline SVG for simple charts (crisp, tiny), Chart.js/ECharts for interactivity; add tooltips, keyboard focus, `aria-label` summarising the chart, responsive `viewBox`, prefers-reduced-motion.
- Always plot real data supplied or generated by code in the workspace; label illustrative data as such.
